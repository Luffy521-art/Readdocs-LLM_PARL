### 论文题目：奖励学习的双层优化：外层反馈与超梯度更新 <br>
  主要研究一个问题：奖励模型给出的分数看起来越来越好，是否真的能让大模型的数学题正确率提高？现在的代码已经有“奖励模型给分、PPO训练策略、再更新奖励模型”的基本流程。接下来准备增加一个外层数据集，用模型训练后的外层的题目集答题表现来判断奖励模型是否有用，再把这个结果反馈回奖励模型。

<br>
### 研究思路<br>
  训练时分成两层：内层先用奖励模型给出的 token 级奖励训练策略模型，让模型生成更好的数学答案；外层再拿一批没有参与内层训练的题目，检查训练后的模型能不能更好地生成标准答案。如果外层表现变好，就说明当前奖励方向比较合理；如果外层表现变差，就通过超梯度把这个信息传回奖励模型，让奖励模型调整自己的参数。这样，奖励模型的目标就从“尽量拟合 API 分数”变成“既参考 API 分数，又真正帮助策略模型提高答题正确率”。第一阶段先实现少量 PPO 步骤的可微更新，验证梯度确实能够从外层答案损失传回奖励模型，再逐步增加训练规模。

<br>
### 实验方案<br>
实验先在项目已有的 CMATH 数据上进行，小规模数据主要用来检查流程和验证梯度，不能直接用来证明方法一定适用于所有数学任务。数据分成内层训练集、外层训练集、开发集和测试集：内层训练集用来做 PPO，外层训练集用来更新奖励模型，开发集用来选择模型(训练过程中定期测试不同检查点，选择表现最好的模型)，测试集只在最后评估。实验会比较最终答题正确率，同时记录训练时间、生成 token 数、显存和 API 调用成本。还要做几组消融实验，例如去掉外层反馈、去掉 API 监督、改变外层题目数量，以及比较不同的 PPO 展开步数，确认效果究竟来自超梯度还是仅仅因为额外看到了标准答案。

<br>
### 对比算法<br>
  主要比较五类方法：不训练的初始模型（即基类模型）、单PPO、只用API分数更新奖励模型的方案、当前代码中的LLM_PARL实现，以及PRIME。PRIME 也是一种在线更新奖励的方法，它用模型和参考模型的 token 概率差来产生过程奖励，再根据答案对错更新奖励模型，但它的重点是如何得到稠密过程奖励，并不是通过超梯度评价奖励模型。最后将本文方法与这些基线放在相同模型、相同数据和尽量相同计算量下比较，重点观察外层反馈和超梯度是否能带来更高的数学题正确率。
